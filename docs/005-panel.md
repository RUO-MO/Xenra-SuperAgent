# 005 面板

[English](005-panel.en.md) · 中文

在 DeepSeek Harness Web 的侧栏里点开 **Xenra-SuperAgent**（锤形图标，排在侧栏面板列表靠前的位置）即可监管智能体。面板只有三个标签页——**首页**、**工单**、**设置**——每个回答一个具体问题，其余细节收进它们里面。本文档建立在 [000 理念](000-philosophy.md) 到 [004 提示词](004-prompts.md) 之上。

面板不直接读写状态：它通过只监听回环地址的管理接口（`/orchestrator/api/`）读写，请求带同源标记，因此页面旁边的其他程序无法借它改配置或停工单。宿主在启动时先注册这些路由，再去跑部署检查，所以配置有问题时面板照样打得开。

## 三个标签页

| 标签页 | 回答的问题 | 显示内容 |
| --- | --- | --- |
| 首页 | 现在有需要我处理的事吗？ | 一句话的运行状态、系统问题、等你处理的工单，以及折叠起来的执行器计数与两个诊断视图的入口 |
| 工单 | 某件工作现在做到哪一步？ | 执行器状态、暂停控制、按阶段过滤的工单列表，以及单张工单的详情页 |
| 设置 | 它按什么规则、用哪个账号、在哪个目录里工作？ | 来源（状态与卡片）、评估、执行、提示词的配置，以及收在 **高级视图** 下的 **线程与触发** 与 **判断记录** |

页头常驻四件事：标题、搜索框、术语表 (?) 按钮，以及 **打开主 Session**；主 Session 尚未建立时该按钮不可用。面板每 5 秒轮询一次，文档隐藏时退避到 6 倍间隔；当前路由与设置分组记在会话存储里，刷新后回到原处。

## 首页

首页从上到下回答"现在需要我吗"，顺序固定：

1. 一句话状态。
2. **系统问题**，只在真的有问题时出现，每条给出处理它的动作。
3. **待处理工单**，列出等你回话或验收的工单。
4. **执行情况**，默认折叠。

状态行有四种措辞：正常时"运行正常，没有等你处理的事。"；有工单等你时"有 N 件工单等你处理。"；处理暂停时"处理已暂停，新的请求不会开始。"；部署还没配好时"还需要完成配置才能开始工作。"。配置问题与暂停优先于其他两种。

### 系统问题

| 问题 | 含义与动作 |
| --- | --- |
| 部署检查未通过，xenra-superagent 暂不接单 | 启动检查失败，附修复位置与 **重新检查**，点标题打开修复它的设置（来源卡片，或部署页）；飞书机器人检查失败只写"飞书机器人检查未通过，飞书来源暂停"，飞书来源单独暂停 |
| 没有运行中的来源，不会收到任何触发 | 所有来源都未启用或未安装，**去打开来源** 打开设置 › 来源 |
| 没有人能发起工作：各来源上的名单都为空，任何请求都不会成为工单 | **去添加** 打开设置 › 评估的名单 |
| 处理已暂停：不开始新的评估，不派工，不发送回复 | 附 **恢复处理**，确认后恢复 |
| {来源} 来源异常 | 某个来源的健康项报错，附详情与一句说明，点标题打开设置 › 来源里对应的卡片 |
| 运行异常：{健康项} | `runtime`、`models`、`worker` 等健康项报错，附原始详情；`evals` 不在这里，它由下一条逐个列出 |
| 评估超时未决定：{线程} | 某个线程上的评估已过截止时间，点标题打开该线程 |
| 评估未完成：{线程} | 最近一小时内、该线程之后没有新判断的未完成决定，附 **重新评估** 与 **不再提示** |
| {来源} 回复发送失败（已重试 {次数} 次） | 发往某个来源的消息连续失败，附尝试次数与错误，点标题打开对应的来源卡片 |

### 待处理工单

**待处理工单** 一栏按阶段 `person` 列出工单。每行给出阶段标签（待回答、待验收、待处理受阻、待处理失败、输入未送达）、涉及的线程、未送达输入数，以及一句说明或问题原文；点标题进入详情页。直接可用的操作是 **去{来源}回答**、**重试**、**打开 Session** 与 **停止**，只在适用时出现。栏头是计数；有工单时还给出 **查看全部工单**，它打开工单页的进行中列表。没有这样的工单时只写"没有待处理的工单。"。

### 执行情况

**执行情况** 折叠区里是这台机器如何跑：**执行中**（运行中的执行器 Session / 并行工单数上限）、**排队** 的工单数与 **等待新触发** 的工单数。前两个链到工单页的"进行中"，后一个链到"等待新触发"。折叠区底部还有 **线程与触发** 与 **判断记录** 两个诊断视图的入口。部署尚未配置时，三个计数换成一句"执行器等待部署检查"。

## 工单

工单页第一行是执行器状态：**执行器运行中**、**处理已暂停** 或 **执行器等待部署检查**；部署检查通过时再给出 **执行中**（运行中 / 上限）与 **排队** 两个数字，右侧是 **暂停处理** 或 **恢复处理**，两者都需确认。标题"状态"旁的 (?) 说明这一页看什么，右侧的 **设置** 直接打开设置 › 执行。

下面按阶段过滤：**进行中**（默认，所有未结束的工单）、**待处理**、**执行中**、**等待新触发**、**已结束**。每行是一张工单：阶段标签（待回答、执行中、等待新触发，已结束的则写结果，如已完成、PR 已合并、人工停止）、涉及的线程、未送达输入数、时间或问题原文，以及适用的 **去{来源}回答**、**重试**、**打开 Session** 与 **停止**。**等待新触发** 顶部说明执行器已结束当前回合、没有提问，新触发会唤醒这些工单。超过一页时给出 **加载更多**。

### 工单详情

点开工单进入详情页。页头是标题、回到上一步的返回按钮，以及适用的 **打开 {来源} 原文**、**重试** 与 **打开 Session**。

状态行给出阶段、**授权** 强度、**发起**（来源与发送者）与 **更新** 时间；已结束的工单再加一行结果，例如"PR 已合并""无需处理""人工停止"。有 **待人工决定** 时，问题原文显示在顶部横幅里，并附 **去{来源}回答**；执行器报告失败或受阻时，报告摘要显示在横幅里；向执行器送达输入失败时，错误另起一条横幅。

**授权详情** 一节给出决定、理由、命中的与未命中的规则、研判方向与方向证据，然后是范围、依据事实（发送者、如何被准入、接收范围单元格、接单模式、命中的规则）和策略版本；策略版本可点击跳到设置 › 评估 的历史记录。未送达的输入单列一栏，并说明原因：等待送达、处理已暂停，或送达失败后需要重试。订阅的线程一栏列出该工单正在跟的线程。

其余细节折叠在直接操作之下：派工列表（每份的报告与起止时间，工单恢复过或移交过、因而有多份派工时才会出现）、执行环境变量、渠道链接、已送达的输入，以及工单 id、执行目录等标识。底部是 **停止** 的危险操作区。

## 设置

设置页左侧是导航，右侧是表单。导航先列四个日常分组——**来源**、**评估**、**执行**、**提示词**——再是 **高级视图** 一组，含 **线程与触发** 与 **判断记录**。每个设置块只有一个保存栏，只在有改动、正在保存或保存失败时可见；草稿在刷新后仍然保留，并会与他人的保存做三方合并。

- **来源：** 分组顶部先是各来源的状态，再是配置它的卡片——"为什么什么都没发生"和"监听的是哪个仓库"是同一个来源的两个问题，所以在同一页回答。状态一栏的标题"状态"旁有 (?) 说明，每行给出状态（运行中、启动中、待处理、出错、已关闭、插件未安装、等待部署检查）、**24 小时到达** 与被过滤的计数、**最近** 时间；配置问题写明缺什么，并给出 **去设置** 跳到那张卡片。非零时才出现两个折叠区：**24 小时内最近被过滤的触发**（发送者、内容、原因、时间）与 **24 小时内放弃发送的消息**（对话已无法接收，或来源已不再监听它）。部署层面的问题会显示在这一栏顶部，附 **去修正**。
  每张卡片含开关、字段、已验证的账号事实、折叠的 **高级** 字段，以及 **保存** 会重启插件的提示；改动会影响部署检查的字段、而又有派工在运行时，保存栏提示这会中断它们。GitHub 提供 **监听的仓库**、**智能体的 GitHub CLI**、**接收仓库里的新 Issue**、**接收仓库里的新 PR**、**接收仓库里的评论** 与 **接收默认分支的 CI** 四个开关，高级里是 **轮询间隔 / 秒** 与 **连续失败几次后报告异常**；飞书提供 **机器人的 lark-cli**、**接收的群**（每群"仅 @"或"全部消息"，群名可 **刷新群列表**）、**其他群**、**接收私聊**，高级里是 **每页消息数** 与原消息链接的查询时限。
- **评估：** 先是策略版本（前 8 位）与接单规则列表，可新增、复制、启停、删除与改说明；然后 **在各来源上** 每个来源一个页签，含能发起工作的账号名单、飞书的 **同步来源群** 与 **立即同步**、机器人名单和准入表；最后是评估设置：接单模式、单次评估时限与研判模型。**立即同步** 在没指定同步来源群时不可用，有未保存改动时点击会提示先保存或放弃。
- **执行：** 执行器模型、**并行工单数**、**执行目录的根目录**（留空即 `<stateDir>/work`，字段下方写出实际使用的默认路径）、**准备命令**、折叠的 **可用的环境变量**（点键名把它按 `"$键名"` 插到准备命令的光标处）与 **禁止调用的命令**。
- **提示词：** **编辑** 修改三个团队小节、内置分段和技能；内置分段可重置，模板会列出它必需的占位符，被编辑过的标记为 **已改**。**完整提示词** 按角色与技能显示组装后的文本，可与已保存内容或默认值对照，并支持整份复制。**历史** 列出各版本、改动过的段落、恢复某个版本或默认值，以及每个 Session 正在使用的修订号。
- **部署：** 这个分组没有左侧的导航入口——日常只在部署检查出问题时需要它，首页的系统问题会直接指过来；也可以在 DeepSeek Harness 的插件管理器里打开本插件，那里是同一份表单。页面上先是启动问题及 **重新检查**，然后是 **本机设置** 一节（**状态目录**）与 **上限** 一节：**提示词配置的最大字符数**、**一次研判可读的线程页数**、**一次上下文读取的时限 / 毫秒**。保存的上限立即生效，无需重启；状态目录必须是绝对路径，改动后插件按新目录重新挂载，页面会提示这一点。插件管理器那一份还多列出由来源设置得出的仓库、智能体账号与飞书机器人；DSH 不提供可写表单或浏览器不在本机时，这些字段以只读方式显示。

### 高级视图

**线程与触发** 与 **判断记录** 原本是两个顶级标签页，现在收在设置里：它们回答"为什么"，只在追查时才需要。打开后左侧的日常分组不再高亮，顶部导航停在 **设置**；点回任一日常分组即离开。

- **线程与触发** 先给标题"状态"与一句说明，再按 **已被订阅**（默认）、**评估中**、**24 小时内有新触发**、**全部线程** 过滤线程。每行给出阶段（已订阅、评估进行中、排队 N、工单已结束、未订阅、轮询失败）、最近一条触发、扇出给哪张工单与时间；点标题进入线程页，悬停标题可看轮询错误。
- **判断记录** 按 **接单与续做**（默认）、**停止**、**忽略**、**未完成**、**全部** 过滤决定，并可切到"仅过去 24 小时到达的触发"。每条决定显示结果、理由、命中的规则与时间，点击进入对应工单，或跳到线程里那条触发；观察模式下"本会接单"的忽略有单独的标签。处理已暂停时，顶部说明新的触发只被记录、不会被评估，并给出 **在执行状态中恢复** 的链接。

### 线程页

线程页显示来源、最近与创建时间、原始链接、正在进行的评估（触发数、强度、截止时间）、轮询错误、订阅的工单、折叠的决定列表、关联线程，以及按时间倒序的触发时间线。

每条触发带去向标签：已排队等待评估、评估进行中、已过滤（附原因）、决定结果（忽略除外）、已送达工单、扇出到 N 个工单；交回过的消息写明是哪张工单、为何交回。人发的触发在满足条件时给出 **重新评估**：来源过滤了它、它的评估未完成、执行器仍持有它，或它送达了工单却没有任何有效判断。连续来自同一发送者的自动消息折叠成一行，只显示最新一条。

有工单订阅时，页面底部是 **取消订阅**：确认后丢弃该线程上全部工单的订阅，新触发不再扇出，直到下一次接单或挂载。这个页面上的写操作只有两个：把某条触发送进评估，以及取消订阅。

## 首次配置引导

安装还没配置好时，面板正文换成首次配置引导，三个标签页隐藏；页头的搜索、术语表与 **打开主 Session** 仍在。触发条件是 GitHub 来源的仓库为空、智能体 CLI 为空，或该来源的策略名单为空。部署层面与飞书机器人的问题（例如 git 太旧、环境准备失败、机器人身份没配好）不是这几步能解决的，它们不触发也不挡住引导，仍然以系统问题的形式显示在首页。

四个步骤按依赖顺序排列，当前一步展开，其余只显示标题与序号：

1. **监听仓库与账号。** 仓库写成 `owner/name`，例如 `octocat/Hello-World`；再填智能体 CLI 的命令名或路径，例如 `gh-agent`，智能体以它登录的账号行事，提交和评论都显示在这个名字下。**两项一起保存**，因为 GitHub 来源把仓库和账号当作一个整体校验（`SETUP_FIELDS.github`）：它会立刻用这个 CLI 去核对账号能否推送到这个仓库，缺任何一项都会失败。所以两项都填好，**下一步** 才可用。
2. **接飞书（可跳过）。** 团队在飞书群里提需求时，在这里填机器人的 `lark-cli`，它写进飞书来源的卡片。只用 GitHub 的话点 **先不接飞书** 直接跳过，这一步不写任何东西；飞书来源本身默认启用，没有 CLI 就一直空闲，不影响 GitHub 的工作。若这个 profile 关掉了飞书来源，这一步会说明这里填了也不会生效，只提供跳过。
3. **谁可以派活。** 先回显第一步保存的仓库，再填一个 GitHub 账号加进这个来源的名单；可以只填自己。
4. **在哪里干活。** 每个工单一个目录；留空用默认位置，填已有克隆的上级目录就在那里工作。

第一步写 GitHub 来源，第二步写飞书来源（跳过时不写），第三步写策略，第四步写执行器。**下一步** 或 **完成** 保存后立刻生效，所以中途关掉页面也不会丢；保存会重启插件时，面板提示正在重启并自己重连。**上一步** 回到前一步。某一步被拒绝时，原因显示在那一步下方并留在屏幕上，而不是弹一条会消失的提示。底部是 **跳过，以后在设置里配** 与 **直接打开设置** 两个链接；两者都关掉整个引导，而第 2 步的 **先不接飞书** 只是跳过那一步。

## 路由与旧链接

面板把当前位置记在会话存储里，刷新后回到原处。旧版本记下的名字仍然打开它当时指向的视图：概览打开首页，执行打开工单，来源打开设置 › 来源，触发与评估打开与 **高级视图** 里相同的线程列表和判断记录，只是顶部导航停在首页，因为这两个视图已经没有自己的标签页。这一页已经不再有的过滤条件会被丢掉，只保留默认视图。

## 搜索

页头搜索按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发，最多 20 条；原消息中缺失的飞书链接，只有在当前进程生命周期内宿主读取过它之后才能被搜到。搜索同时按 `#12` 或 GitHub URL 之类的引用查找线程，按标题或匹配的线程查找工单（最多 10 张）。

结果按工单、线程、触发的顺序分组，并给出"找到 N 个工单、N 个线程、N 条触发"；触发截到 20 条时改为提示缩小范围。被来源过滤的触发没有线程，因此显示过滤原因而不是链接。

## 术语表

页头的 (?) 打开术语表：按角色、来源设置、线程与触发、判断记录、工单分组的双语对照表，加上状态颜色图例（完成、执行中、等待、失败、已结束）与各状态取值的双名列。它遵循 [001 领域模型](001-domain.md) 的术语表，是面板与文档对齐的依据。

## 本地化

面板使用 DeepSeek Harness 的设计令牌与控件，跟随宿主语言显示中文或英文。界面只显示一种语言；文档、代码与工具名使用英文术语，术语表把两者并列给出。

## 破坏性操作

需要确认的操作都先用弹窗说明后果，再由 **确定** 执行，**取消** 关闭弹窗。

| 操作 | 出现位置 | 确认时说明 |
| --- | --- | --- |
| 停止 | 首页、工单列表、工单详情底部 | 当前派工结束，Session 与执行目录保留；停止收回授权，之后线程里的消息不再恢复它 |
| 重试 | 首页、工单列表、工单详情页头 | 结束当前派工并重新派工；授权和订阅不变 |
| 取消订阅 | 线程页底部 | 新触发不再扇出给工单，直到下一次接单或挂载 |
| 暂停处理 / 恢复处理 | 工单页、首页的系统问题 | 暂停后来源继续记录触发，但不开始新的评估、不派工、不发送回复；恢复后继续 |
| 重新检查 | 首页的系统问题、来源卡片上的问题行、部署页 | 只有存在进行中的派工时才先确认：会重启插件并中断这些派工 |

其余改动不弹确认，但会写清后果：来源卡片里影响部署检查的字段会重启插件，状态目录会重新挂载。**不再提示** 只是收起一条未完成的评估，不算破坏性操作。

## 原则

1. **聚焦真正重要的事。** 每个元素都要回答三个标签页之一的问题，否则删掉。数字只在会改变监管者行为时才出现。
2. **定义精确。** 分类有可检查的定义、互斥且覆盖所有情况，就像工单阶段那样。标签说明这一行在等谁、需要什么，而不是内部状态码。
3. **每个概念只有一处。** 工单在工单；来源、规则、执行环境与提示词在设置；线程与触发、判断记录在 设置 › 高级视图。首页只汇总它们并链接过去，不再重复成一个详细视图。
4. **领域结构。** 面板使用领域术语。内部标识只出现在折叠的细节里，能解析出名字的地方用名字代替标识。
5. **状态诚实。** 计数等于它链接到的列表长度：系统问题的条数就是它列出的行数，待处理工单的计数就是这一栏的行数。任何状态都不与其他事实矛盾。
6. **默认安静。** 健康状态不占额外空间，执行器计数折进 **执行情况**。问题必须是可行动的；一次性的网络错误不算。需要人处理的行直接给出它的操作。页面说明控制在一句话，更多细节放进 (?) 提示。
7. **控件一致。** 使用 DeepSeek Harness 的设计令牌与控件行为。同样的信息在面板各处应看起来一样。每个设置块只有一个保存栏，破坏性操作都要确认。
